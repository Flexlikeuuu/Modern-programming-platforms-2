# Лабораторная работа: Многопользовательская веб-игра в режиме реального времени

Многопользовательская игра "Pixel Battle" (битва за территорию на пиксельной сетке 100x100 — 10 000 ячеек).

## Онлайн демо (развернутое приложение)
🌐 **[https://lab4spp2stepanenko.bonto.run/](https://lab4spp2stepanenko.bonto.run/)**

## Реализованные требования

1. **Мгновенная синхронизация через WebSockets**:
   - Обновление ячеек игрового поля, рейтинг игроков и журнал событий транслируются всем подключенным клиентам мгновенно.
2. **Только JavaScript, без фреймворков**:
   - Сервер: чистый Node.js (встроенные модули `http`, `crypto`, `node:sqlite`, библиотека `ws` для WebSocket).
   - Клиент: чистый HTML5 Canvas, CSS3 и Vanilla JavaScript (DOM API, `WebSocket`). Без React, Vue, Angular и других фреймворков.
3. **Хранение данных в реляционной базе данных (SQLite)**:
   - Состояние сетки, пользователи, сессии, статистика очков и журнал событий хранятся в реляционной базе данных SQLite (`data/game.db`).
   - Используется встроенный в Node.js движок `node:sqlite` без внешних нативных зависимостей (идеально для Alpine Linux и контейнеров Bonto), с отказоустойчивым механизмом.
   - Данные надёжно сохраняются между перезапусками сервера.
4. **Привязка к аккаунтам (Регистрация и Вход)**:
   - Полноценная система пользователей: регистрация и авторизация по логину и паролю.
   - Безопасное хеширование паролей солью через встроенный `crypto.scryptSync`.
   - Сессионные токены сохраняются в браузере — при обновлении страницы вход сохраняется автоматически.
   - Возможность играть как под своим аккаунтом (сохранение личного счёта и цвета), так и в гостевом режиме.
5. **Масштабное игровое поле 100x100 на HTML5 Canvas**:
   - 10 000 интерактивных ячеек с рендерингом через Canvas со скоростью 60 FPS.
   - Поддержка плавного зума (колёсико мыши или кнопки `+` / `-` / `100%`) и панорамирования (перетаскивание поля зажатой кнопкой мыши).
   - Информативная панель координат и владельца при наведении на любую ячейку.
6. **Конкурентный доступ и разрешение конфликтов (8-10)**:
   - Механизм Optimistic Concurrency Control (OCC) на уровне базы данных SQLite.
   - Каждая ячейка хранит номер версии `version`. При изменении ячейки клиент передает `expectedVersion`.
   - Если версия на сервере уже изменилась (другой игрок занял ячейку раньше), запрос отклоняется, фиксируется конфликт, ячейка подсвечивается анимацией, игрок получает уведомление, а поле актуализируется.
7. **Работа при потере интернет-соединения (8-10)**:
   - При отключении сети состояние сохраняется в `localStorage`.
   - Действия игрока сохраняются в локальную очередь `offlineQueue` и визуально выделяются на холсте.
   - При восстановлении связи клиент автоматически переподключается и отправляет накопленные действия на сервер с проверкой версий.
8. **Кулдаун 5 секунд**:
   - Защита от спама: после установки пикселя игрок ожидает 5 секунд (с таймером обратного отсчёта и серверной валидацией).

## Запуск приложения локально

1. Установка зависимостей:
```bash
npm install
```

2. Запуск сервера:
```bash
npm start
```

3. Открыть в браузере:
```
http://localhost:3000
```
